这份落地指南将前端（Node.js）、后端调度（Java）、计算引擎（C++）与构建服务（Python）整合成一条**可执行、可度量、高精度**的工程自动化流水线。


## 阶段二：四端关键入口的静态特征提取（ast-grep）

通过声明确定性的语法模式，从代码中抓取所有跨语言调用的**确定性锚点**，避免大模型“瞎猜”。

### 1. 前端（Node.js / TS）：提取 API 请求

创建规则文件 `sg-rules/frontend-api.yml`：

```yaml
id: frontend-api-call
language: typescript
rule:
  pattern: axios.post($URL, $PAYLOAD)

```

执行提取命令并导出结构化 JSON：

```bash
sg scan -r sg-rules/frontend-api.yml ./frontend-repo --json > fe_apis.json

```

### 2. 后端（Java）：提取 Controller 路由与 DTO

创建规则文件 `sg-rules/java-controller.yml`：

```yaml
id: java-controller-endpoint
language: java
rule:
  pattern: |
    @PostMapping($URL)
    public $RET $METHOD(@RequestBody $DTO $REQ) {
      $$$BODY
    }

```

执行提取：

```bash
sg scan -r sg-rules/java-controller.yml ./backend-repo --json > java_endpoints.json

```

### 3. 后端到底层（Java 调用 C++ CLI 或 JNI）

提取 Java 端拉起进程的命令行调用点：

```yaml
id: java-exec-cpp
language: java
rule:
  pattern: new ProcessBuilder($$$CMD)

```

### 4. 引擎端（C++）：提取场景解析与核心入口

提取 C++ 解析 JSON 的结构映射点：

```yaml
id: cpp-parse-scenario
language: cpp
rule:
  pattern: $JSON[$KEY].get<$TYPE>()

```

执行提取：

```bash
sg scan -r sg-rules/cpp-parse-scenario.yml ./engine-repo --json > cpp_params.json

```

## 阶段三：跨语言图谱构建与路径寻径

编写图拼接与寻径脚本 `trace_pipeline.py`，根据 HTTP URL、进程参数与接口名称，将四端节点组装为连通图，并按业务入口切片。

```python
import json
import networkx as nx

def build_and_slice_graph():
    G = nx.DiGraph()

    # 1. 注入前端节点与边
    with open("fe_apis.json") as f:
        fe_data = json.load(f)
        for item in fe_data:
            url = item["metaVariables"]["single"]["URL"]["text"].strip('"\'')
            file_path = item["file"]
            G.add_node(f"FE::{file_path}", type="frontend", url=url)
            G.add_node(f"API::{url}", type="endpoint")
            G.add_edge(f"FE::{file_path}", f"API::{url}", relation="CALLS_HTTP")

    # 2. 注入 Java 节点与边
    with open("java_endpoints.json") as f:
        java_data = json.load(f)
        for item in java_data:
            url = item["metaVariables"]["single"]["URL"]["text"].strip('"\'')
            method = item["metaVariables"]["single"]["METHOD"]["text"]
            file_path = item["file"]
            G.add_node(f"JAVA::{file_path}#{method}", type="backend_method")
            G.add_edge(f"API::{url}", f"JAVA::{file_path}#{method}", relation="HANDLED_BY")
            # 建立由 Java 向 C++ 进程拉起的桥接关系
            G.add_edge(f"JAVA::{file_path}#{method}", "CPP::main.cpp#run_sim", relation="EXEC_CLI")

    # 3. 注入 C++ 引擎节点
    G.add_node("CPP::main.cpp#run_sim", type="engine_entry")

    # 4. 指定起点寻径并提取子图链路
    target_api = "API::/api/v1/sim/jobs"
    paths = list(nx.all_simple_paths(G, source="FE::src/api/sim.ts", target="CPP::main.cpp#run_sim"))
    
    with open("sliced_subgraph.json", "w") as out:
        json.dump({"chains": paths}, out, indent=2)
    print(f"成功提取业务链路路径: {len(paths)} 条")

if __name__ == "__main__":
    build_and_slice_graph()

```

## 阶段四：AI 业务链解析、文档生成与防幻觉质检

### 1. 组装 Prompt 驱动大模型生成资产

将提取出的代码切片与路径传入大模型（或 understand-anything 引擎），设定严格的输出协议。

> **Prompt 规范：**
> “你是系统测试架构师。以下是跨三端调用的确切代码片段及路径拓扑：
> 1. 前端请求文件：`src/api/sim.ts`
> 2. 后端控制器：`SimTaskController.java`
> 3. 底层解析引擎：`main.cpp`
> 
> 
> 请完成三项交付：
> * **交付项 A**：输出标准 Mermaid 时序图，标记关键参数与状态转换。
> * **交付项 B**：提取入参与约束，输出 OpenAPI 3.0 YAML 规范。
> * **交付项 C**：输出 JSON 格式的业务链路调用明细（必须严格包含 `file` 与 `symbol` 字段供校验）。”
> 
> 

### 2. 运行防幻觉质检脚本（Validation Gate）

模型输出 JSON 链路后，必须先跑此质检脚本。**只要出现虚构的文件或函数，立即驳回并重试，不进入后续测试执行。**

```python
import os
import re
import json

def verify_ai_output(ai_chain_json_path):
    with open(ai_chain_json_path) as f:
        chain_data = json.load(f)

    errors = []
    for step in chain_data.get("steps", []):
        file_path = step["file"]
        symbol = step["symbol"]

        # 1. 验证文件物理存在性
        if not os.path.exists(file_path):
            errors.append(f"幻觉文件: 路径不存在 -> {file_path}")
            continue

        # 2. 验证符号/方法是否真实存在于源码中
        with open(file_path, "r", encoding="utf-8", errors="ignore") as src_file:
            content = src_file.read()
            if not re.search(rf"\b{re.escape(symbol)}\b", content):
                errors.append(f"幻觉符号: 在文件 {file_path} 中未找到符号 -> {symbol}")

    if errors:
        print("[质检未通过] 发现大模型幻觉，中断流程:")
        for err in errors:
            print(f"  - {err}")
        return False

    print("[质检通过] 所有文件与调用符号真实有效！")
    return True

```

## 阶段五：自动化仿真调度与 OPNET 基线比对

通过 Python 测试驱动脚本执行闭环：调度后端接口 $\to$ C++ 引擎运行输出 $\to$ 与历史 OPNET 基准数据进行容差对齐。

```python
# test_sim_opnet_alignment.py
import pytest
import requests
import json
from deepdiff import DeepDiff

BASE_URL = "http://localhost:8080/api/v1"

def test_simulation_run_and_opnet_compare():
    # 1. 自动化触发调度接口
    payload = {
        "topology_type": "mesh",
        "node_count": 50,
        "traffic_rate_mbps": 100
    }
    resp = requests.post(f"{BASE_URL}/sim/jobs", json=payload)
    assert resp.status_code == 202
    job_id = resp.json()["job_id"]

    # 2. 获取本次 C++ 仿真引擎输出的性能与业务指标
    # 假定引擎运行完成生成结果 JSON
    with open(f"/sim_output/{job_id}/metrics.json") as f:
        actual_sim_metrics = json.load(f)

    # 3. 读取 OPNET 官方基线基准数据
    with open("fixtures/opnet_baseline_mesh_50.json") as f:
        opnet_baseline = json.load(f)

    # 4. 使用 DeepDiff 进行浮点数学公差比对 (允许 3% 偏差)
    # math_epsilon=0.03 表示指标相对波动在 3% 内视为一致
    diff = DeepDiff(
        opnet_baseline, 
        actual_sim_metrics, 
        significant_digits=2, 
        ignore_order=True,
        math_epsilon=0.03
    )

    # 若差分存在且超出容限，输出具体异常指标
    assert not diff, f"仿真指标与 OPNET 基准对齐失败，偏差详情: {diff}"

```

## 完整执行指引与日常维护

1. **触发代码扫描与图谱更新:** 耗时约 1-3 分钟，推荐挂载于 CI 或本地 pre-push.
执行 `ast-grep` 扫描前后三端与构建仓库，输出符号 JSON；运行 `trace_pipeline.py` 生成包含最新调用的依赖子图。


2. **AI 业务链路提取与契约同步:**
将子图数据传给模型，增量生成最新的 Mermaid 时序图与 OpenAPI 文档，自动更新到工程文档目录。


3. **防幻觉质检阻断:**
运行 `verify_ai_output.py`。若模型生成的调用链引用了错误的代码符号，CI 阻断并告警；若验证通过，放行后续测试。


4. **接口用例衍生与并发执行:**
测试框架根据契约自动装配入参，使用 `pytest` 并发运行调度接口测试，向底层引擎派发真实任务。


5. **仿真结果收集与差分报告出具:**
运行 `DeepDiff` 脚本，将仿真引擎输出的指标矩阵与 OPNET 基线比对，结果自动汇总进 Allure 测试报告看板。
