# remote-context —— 远程/本地工作上下文管理技能

## 这个技能解决什么问题

避免"每执行一条命令都要重复写 `ssh 主机名`、每次都要重新说明在哪台机器、在哪个目录"的啰嗦。本技能负责**建立并维持一个当前工作目标**，包含三要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| 目标主机 | `local` 或远程主机（ssh 别名） | `SERVER_252` |
| 工作目录 | 在该主机上工作/落盘的目录 | `/data/work` |
| 登录用户 | 远程连接使用的用户 | `luli` |

一旦建立，**本对话后续所有命令默认作用于该主机与目录**，直到用户显式切换目标或退出上下文。

## 触发时机

满足任一条件即使用本技能：

- 用户说固定触发词 **"分析问题"**；
- 用户要求**连接/登录/切换到**某台远程主机或虚拟机；
- 用户要求**切换当前工作目标**（远程 → 另一台远程，或远程 → 本地）；
- 用户描述"在某台机器上做某事""远程执行 xx"，隐含需要先建立目标；
- 用户要求查看/退出当前上下文。

> 本技能只负责"建立与维持上下文"，不负责具体的业务分析；建立好目标后，按用户随后说明的具体任务执行。

## 工作流程

### 第一步：确定目标主机

1. 判断目标是**本地**还是**远程**。
2. 用户未指明主机时，**主动用 `question` 询问**要连哪台：本机，还是某个 ssh 别名。
3. 远程目标优先读取本机 `~/.ssh/config`，用用户给出的主机名/IP 匹配 `Host` 别名。
   - 命中别名 → 直接用 `ssh <别名>`。
   - 未命中 → 再向用户询问 `host/user/port`（或请其补一条 `~/.ssh/config`）。
   - 可在对话中列出 `~/.ssh/config` 里可选的主机名，方便用户挑。

### 第二步：输出可达性

建立连接后，先输出一份**可达性报告**，让用户确认目标无误、网络可用：

**本地目标：**

```bash
hostname; whoami; pwd
cat /etc/os-release | grep -E '^PRETTY_NAME|^VERSION'
uname -m; nproc
ping -c 2 -W2 127.0.0.1    # 本机回路，确认网络栈可用
```

**远程目标（一次 ssh 调用带出关键信息）：**

```bash
ssh -o ConnectTimeout=5 -o BatchMode=yes <别名> \
  'hostname; whoami; pwd; grep PRETTY_NAME /etc/os-release; uname -m'
# 网络延迟/丢包（可从本机发起，也可在远端发起）
ping -c 3 -W2 <别名或主机IP>
```

**可达性报告模板**（输出给用户）：

```markdown
## 目标可达性 - <主机名 / local>
- 连接：✅ 已连通（ssh 别名 `SERVER_252` / 本机）
- 主机名 / 用户：<hostname> / <user>
- 系统：<PRETTY_NAME> / <架构>
- 网络：延迟 <avg> ms，丢包 <loss>%
- 工作目录：<dir>（✅ 存在 / ⚠️ 不存在）
```

只要有一项失败（连不上、丢包 100%、目录不存在），要如实报告并给出下一步建议，不要假装成功。

### 第三步：切换到工作目录

1. 工作目录**由用户指定**（每次建立上下文时确认）。
2. 本地目标：用 Bash 工具的 `workdir` 参数，或 `cd <dir> && <cmd>`。
3. 远程目标：先验证目录是否存在（只读）：
   ```bash
   ssh -o BatchMode=yes <别名> 'test -d <dir> && echo exists || echo missing'
   ```
   - 存在 → 后续命令统一 `cd <dir> && ...`。
   - 不存在 → **询问用户**是否创建（创建属写入操作，需确认），或改到其它目录。

### 第四步：记住上下文（本技能的关键）

用一个明确的声明**固化当前上下文**，并在之后严格遵守：

```markdown
✅ 当前工作上下文已建立
- 目标主机：SERVER_252（ssh 别名） / 或 local
- 工作目录：/data/work
- 登录用户：luli
- 后续本对话的所有命令默认在该主机、该目录下执行；如需切换目标或目录请告知。
```

**后续命令路由规则：**

| 目标 | 命令写法 |
|------|----------|
| 本地 | 直接执行，可用 `workdir` 参数或 `cd <dir> && <cmd>` |
| 远程 | `ssh -o BatchMode=yes <别名> 'cd <dir> && <cmd>'` |
| 远程多行脚本 | `ssh <别名> bash -s <<'EOF' ... EOF`（heredoc，避免引号地狱） |

**上下文生命周期：**

- **查看**：用户问"当前在哪台机器"→ 输出当前 host + dir。
- **切换**：用户说"切换到 xxx / 连另一台 / 回到本地"→ 重新走一遍本流程，并覆盖上下文，明确告知"已从 A 切换到 B"。
- **退出**：用户说"退出远程上下文 / 回到本地"→ 清理上下文，声明"已回到本地，后续命令在本机执行"。

## 与 linux-troubleshoot 的配合

若用户在本上下文中要做故障排查/巡检，可直接衔接 `linux-troubleshoot` 技能：本技能负责"连到哪、在哪干活"，该技能负责"怎么诊断"。两者共享 `~/.ssh/config` 别名与只读安全边界。

## 注意事项

- **安全边界**：连接、可达性验证、`cd`、查看均为只读操作；创建目录、改配置、安装软件等写入操作必须列出命令并等待用户确认（遵循仓库 `AGENTS.md`）。
- **凭据安全**：一律复用 `~/.ssh/config` 与已配置的密钥；**严禁**在对话、脚本或仓库中明文记录密码。
- **非交互**：远程命令统一加 `-o BatchMode=yes -o ConnectTimeout=5`，避免卡在密码/确认交互上；需要 `sudo` 时用 `sudo -n` 探测免密，不满足则提示用户手动执行。
- **一次往返**：远程尽量把多条只读命令合并到一次 `ssh` 调用中，减少往返开销。
- **状态诚实**：每次切换/退出都要显式声明当前上下文，避免用户误以为命令还在旧主机上执行。如果连接中途失败，要明确告知上下文已失效，不能默默继续。.
