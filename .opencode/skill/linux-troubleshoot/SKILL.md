# Linux 运维故障排查与巡检技能

## 适用场景

| 故障类型 | 典型现象 | 诊断剧本 |
|----------|----------|----------|
| 性能问题 | 系统卡顿、CPU/内存/负载高、IO 等待高 | `references/performance.md` |
| 磁盘/存储 | 磁盘写满、inode 耗尽、大文件占用、挂载异常 | `references/disk.md` |
| 服务/进程 | 服务起不来、进程异常退出、端口未监听 | `references/service.md` |
| 网络 | 网络不通、延迟高、DNS 解析失败、端口不通 | `references/network.md` |
| 系统巡检 | 例行体检、健康检查、上机前摸底 | `references/health-check.md` |

当用户未明确故障类型时，先运行 `references/health-check.md` 的全景巡检，再根据异常项深入对应剧本。

## 核心原则（务必遵守）

1. **只读优先**：本技能只执行只读诊断命令（`df`、`free`、`ss`、`journalctl`、`top` 等）。
2. **修复前必须确认**：任何写入性/破坏性操作（重启服务、删除文件、修改配置、`apt`/`yum` 变更、`chmod`/`chown` 等）**只能列出具体命令并等待用户显式确认**，严禁自行执行。这与仓库 `AGENTS.md` 的安全边界一致。
3. **结论先于命令堆砌**：先给用户"发生了什么、根因是什么"，再给证据和建议修复命令，不要把原始输出直接糊给用户。
4. **全程中文**：分析、结论、报告、文档一律使用中文。

## 工作流程

### 第一步：确定目标主机（本机 or 远程）

先判断排查对象是**本机**还是**远程主机**：

- **本机**：直接执行诊断命令。
- **远程主机**：
  1. 优先读取本机 `~/.ssh/config`，用用户给出的主机名/IP 去匹配 `Host` 别名（如 `SERVER_252`、`working-220`）。
  2. 命中别名后，用 `ssh <别名>` 连接，无需再问账号密码。
  3. 若 config 中找不到匹配项，**再向用户询问** `host/user/port`（或让其先补一条 `~/.ssh/config`）。
  4. 连接前先做只读连通性验证：`ssh -o ConnectTimeout=5 <别名> 'echo ok; hostname'`。

> 远程执行约定：所有诊断命令都用 `ssh <别名> '<命令>'` 单次或组合下发；需要多行脚本时用 heredoc 传入，避免交互式登录。

### 第二步：确定工作目录

向用户提示并确认本次工作的**工作目录**（用于保存诊断原始输出与报告）：

- 默认建议：当前仓库下 `diagnostics/<主机名>-<YYYYMMDD-HHMMSS>/`。
- 用户可指定其它目录；确认后 `cd` 进去再开始收集，做到"就地归档、可回溯"。
- 若目录不存在，先创建（`mkdir -p`，这一步是安全的）。

### 第三步：识别故障类型并加载剧本

按下表读取对应 `references/*.md` 获取具体命令与判读标准：

- 性能 → `references/performance.md`
- 磁盘 → `references/disk.md`
- 服务 → `references/service.md`
- 网络 → `references/network.md`
- 不确定/巡检 → `references/health-check.md`

### 第四步：只读诊断并收集证据

1. 按剧本执行只读命令，将原始输出保存到工作目录（本机重定向；远程 `ssh <别名> '...' > <文件>`）。
2. 逐项判读：对照剧本里的"判读标准"识别异常。
3. 对异常项做**下钻**：例如磁盘满 → 定位到具体目录/文件；端口未监听 → 定位到服务与日志。

### 第五步：输出诊断结论与建议修复

向用户输出结构化结论（对话中），包含：

- **现象**：观测到的异常指标。
- **根因**：定位到的直接原因（附关键证据行）。
- **影响**：对业务/系统的影响范围。
- **建议修复**：给出具体命令，但**标注"需你确认后执行"**；破坏性操作要说明风险与回滚方式。

### 第六步：存档与沉淀

1. **工作目录存档**：确保原始输出与一份 `report.md` 落在第二步的工作目录中。
2. **沉淀运维手册**：若本次排查具有可复用价值，按 `AGENTS.md` 规范在 `docs/<领域分类>_<名>/<os>_<env>/` 生成文档（含标准 YAML 文件头），并刷新 `docs/README.md` 总索引。领域分类参考：
   - 性能/系统 → `os_systemd` 或 `os_system`
   - 磁盘/存储 → `os_storage`
   - 服务/进程 → `os_systemd`
   - 网络 → `os_network` 或 `network`

## 远程排查要点

- 优先复用 `~/.ssh/config` 别名；不要在仓库中明文记录密码。
- 远程命令尽量合并为一次 `ssh` 调用（如 `ssh host 'cmd1; cmd2'`）以减少往返。
- 需要持续观察的指标（如 `top`、`iostat`）改用采样模式（`top -bn1`、`iostat -x 1 3`）避免挂起。
- 权限不足时，只读命令可尝试 `sudo -n` 非交互探测是否有免密提权；不满足则提示用户手动执行并回传结果，**不要**在多轮里反复尝试交互式 sudo。
